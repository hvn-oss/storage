> specification. They are not an implemented or installable release.

HVN Storage separates **authority** from **file transfer**. Your application decides who may upload
or download. HVN Storage coordinates durable state, short-lived capabilities, transfer, and trusted
verification. File bytes do not pass through your application server.

## The complete path

1. Your server authorizes one or more files against a named **Upload Route**.
2. HVN Storage creates an **Upload Session** with an independent **File Record** for each file.
3. The browser transfers bytes directly to S3-compatible storage using short-lived capabilities.
4. Trusted server logic verifies the storage key and exact byte size before making a file ready.
5. Your application authorizes each download before HVN Storage issues a short-lived bearer
   capability.
